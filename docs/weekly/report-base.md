## 공통 규칙 (주간 보고 표준 v1.2)

### 산출물
- `{{OUT}}/summary.html`(항상), `{{OUT}}/detail.html`(변경이 있을 때만). 두 문서는 상대 경로(`summary.html`, `detail.html`)로 서로 링크한다.
- `scripts/weekly/template.html`의 뼈대와 CSS를 그대로 쓴다. `sample-summary.html`, `sample-detail.html`은 형식·문체 예시이고 내용은 복사하지 않는다.
- 지난 보고서가 있으면 그 summary.html을 읽어 이미 보고한 항목은 다시 쓰지 않는다.
- 보고 대상은 기간({{START}}~{{END}}) 안에 일어난 일만이다. 기간 밖(보고서를 만드는 날 이후의 작업, 보고 도구·표준·자동화 자체를 손본 작업 포함)은 ①②③ 어디에도 쓰지 않는다. 미push 커밋 수처럼 현재 상태를 세는 항목에서도 기간 밖 커밋의 내용은 설명하지 않고 개수만 쓴다. 기간 안 변경이라도 아직 반영되지 않았거나 상태가 바뀔 수 있는 것은 "보고서를 만든 시점 기준"이라고 밝힌다.

### 섹션
- summary: ①업데이트 요약 → ③추가 개선건 → ④기술 새 소식. ②상세는 detail.html 링크 한 줄.
  - ① 은 사용자가 체감하는 변화 위주. 새 화면이나 바뀐 화면은 스크린샷을 넣는다. 소제목은 번호가 아니라 내용을 말한다(예: "음악 스튜디오", "답변 품질").
  - 머리글 meta에 변경 수(저장소 설정의 단위)와 자동 테스트 수를 적는다. 기록으로 확인한 값만 쓴다.
- detail: ②업데이트 상세. 영역별 표(첫 열 추적 ID · 배경 · 변경 · 검증). 일요일 코드 정리 결과가 있으면 따로 한 절.
- 변경이 없는 주: `summary.html` 하나만 만든다. 첫 문단에 "지난주({{START}}~{{END}}) 업데이트 내용은 없습니다."라고 적고 ③만 쓴다. ④는 쓰지 않는다. detail.html은 만들지 않는다.

### 절대 하지 말 것 (공통)
- 코드 수정·커밋·push·배포. 보고서 폴더 밖 쓰기.
- 운영 프로세스·컨테이너의 재시작·재빌드.
- 운영 데이터 폴더의 파일 목록·내용 읽기. 용량 같은 숫자 확인만 허용한다.
- `.env`·시크릿 파일 열기.
- 로그를 옮길 때는 오류 종류와 횟수만. 개인정보·토큰·비밀번호·경로·IP·사용자 이름은 옮기지 않는다.

### ③ 추가 개선건 (읽기만 한다, 티켓을 만들거나 파일을 고치지 않는다)
실제로 확인된 것만 쓰고, 항목마다 근거(파일, 로그 종류, 커밋 해시, 티켓 번호)를 붙인다. 공통 점검:
- 운영 로그의 지난주 오류를 종류별로 센다.
- 머지됐지만 운영에 배포되지 않은 변경.
- origin 대비 미push 커밋 수.
- 일요일 정리 기록에서 고치지 않고 남긴 발견.
- 지난주 기록에 "한계", "미확인", "후속", "필요", TODO로 남은 것.
저장소별 점검은 저장소 설정에 있다.

### ④ 사용 중인 기술의 새 소식
- 새 릴리스는 WebSearch 또는 공식 릴리스 페이지·GitHub releases API 직접 조회로 찾는다. 어느 쪽이든 날짜와 버전은 공식 릴리스 노트나 GitHub releases·PyPI 페이지를 열어 확인한 값만 쓰고, 검색 요약만 보고 쓰지 않는다. 검색 도구를 못 쓰고 공식 페이지만 읽었다면 문서 메모에 그렇게 적는다.
- 지난주 기간에 나온 릴리스만 표로: 기술 · 우리 버전 · 새 버전(날짜) · 바뀐 점 한 줄 · 영향 · 보안. 링크 포함.
- 영향은 호환성, 쓸 만한 기능, 없음 중 하나로 쓰고, 보안 열에는 보안 수정 여부를 반드시 표시한다.
- 보안 수정이면 advisory 본문(영향받는 조건·버전 범위)을 읽고, 우리 설정·코드(예: 해당 기능을 쓰는지, 서버로 도는 경로가 있는지)로 해당 여부를 확인해 근거와 함께 "해당 / 해당 없음 / 확인 못 함" 중 하나로 쓴다. 버전 범위만 보고 단정하지 않는다.
- 새 소식이 없으면 "지난주에 새 릴리스 없음". 확인하지 못한 항목은 "확인 못 함".

### 스크린샷
- 운영 서버·운영 데이터로 찍지 않는다. 저장소의 `shot-stack.sh`로 격리 스택을 띄워 찍고, 끝나면 반드시 stop 한다.
- 1440×900, deviceScaleFactor 2. 휴대폰 화면이 바뀐 주에만 390×844도.
- 찍을 때마다, 자른 뒤에도 Read로 열어 캡션이 설명하는 요소가 실제로 보이는지 확인한다. 모달·토스트에 가려졌거나 설명과 다르면 다시 찍는다.
- `sips -s format jpeg -s formatOptions 82 -Z 1600`으로 줄여 `{{OUT}}/shots/`에 저장하고 `shots/파일명.jpg`로 참조한다. 필요하면 `sips -c 높이 너비 --cropOffset y x`로 자른다.
- 문서에 "테스트 데이터로 찍은 화면"이라고 한 줄 밝힌다. 스택이 뜨지 않으면 스크린샷 없이 진행하고 그 사실을 적는다.

### 문체
- 한국어 합니다체. 읽는 사람은 이 서비스를 쓰는 사람이다. 내부 클래스·함수명은 상세 문서에만.
- 사람이 쓴 주간 노트처럼 쓴다. 쓰지 않는 것: 이모지, 굵은 글씨로 시작하는 목록, "한눈에 보기", "핵심", "주목할 만한", "~을 통해", "크게 향상", "다양한", "원활한", 세 개씩 짝지은 나열 습관, 모든 문단을 같은 길이로 맞추기, 끝맺음 요약 문단.
- 숫자, 날짜, 티켓 번호·커밋 해시처럼 확인된 사실만 쓴다. 모르면 모른다고 쓴다. 기록에 없는 효과를 지어내지 않는다.
- 글꼴은 시스템 기본(템플릿 CSS 그대로). 외부 글꼴·외부 스크립트 금지. mermaid는 쓰지 말고 표나 문장으로.

### 마무리
- 마지막 출력은 세 줄: 기간, 변경 수, 만든 파일 경로.
