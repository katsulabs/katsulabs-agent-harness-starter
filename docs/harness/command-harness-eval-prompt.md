# 커서 커맨드 하네스 평가 프롬프트

하네스(`.cursor/commands/*.md` 등)를 일관된 기준으로 평가할 때 사용한다.

## 사용법

1. 아래 **평가 프롬프트** 블록 전체를 복사한다.
2. `[하네스 원문]` 자리에 평가 대상 마크다운 전문을 붙여넣는다.
3. 평가 전문가 역할의 에이전트(또는 리뷰어)에 전달한다.

---

## 평가 프롬프트

```
너는 AI 코딩 하네스 평가 전문가다. 아래 하네스를 평가해라.

[평가 방법]
1. 하네스 전문을 읽고 의도(라우팅 판단 → 위임/직접 처리)를 한 줄로 요약한다.
2. 아래 5개 축을 각 10점 만점으로 채점하고, 각 축마다 근거를 2줄 이내로 쓴다.
   - 명확성: 각 단계의 지시가 모호함 없이 단일 해석으로 수렴하는가
   - 견고성: 엣지 케이스(CLI 미설치, claude -p 실패/타임아웃, 판단 애매한 중간 규모 작업)에서 정의되지 않은 동작이 있는가
   - 효율성: 단순 작업에도 불필요한 오버헤드(계획서 출력 등)를 강제하지 않는가
   - 일관성: 단계 간 충돌하는 지시가 없는가 (예: "내부용" 계획서를 "사용자에게 먼저 출력")
   - 실용성: 실제 Cursor 커맨드 실행 환경에서 그대로 동작 가능한가 (PATH 전제, 팀 공유 조건 포함)
3. 시뮬레이션 테스트: 아래 3개 가상 요청을 이 하네스로 처리한다고 가정하고, 각각 어느 단계에서 판단이 흔들리거나 규칙이 침묵하는지 지적한다.
   - AL-06: "이 함수 오타 하나 고쳐줘"
   - AL-07: "모노레포 전체에서 deprecated API를 신규 API로 마이그레이션해줘"
   - AL-08: "테스트가 CI에서만 실패하는데 원인 찾아줘" (단, claude CLI 미설치 환경)
4. 총점(50점 만점)과 함께, 점수를 가장 많이 깎은 문제 상위 3개에 대해 구체적인 수정 문구를 제시한다. 수정안은 기존 문서에 바로 diff로 반영 가능한 형태로 작성한다.

[출력 형식]
- 의도 요약 (1줄)
- 채점표 (축 / 점수 / 근거)
- 시뮬레이션 결과 (요청별 1~3줄)
- 총점
- 상위 3개 수정안 (diff 형식)

[하네스 원문]
(여기에 평가 대상 하네스 전문 붙여넣기)
```
