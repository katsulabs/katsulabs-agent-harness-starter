# Claude Code 라우팅 판단
아래 작업을 실행하기 전에 반드시 다음 순서를 따른다.
## 0단계: 사전 확인 및 override
요청을 읽은 직후, **질문-only/읽기 전용**(설명·의견·동작 질문 등)이면 0~3단계를 모두 생략하고 4단계에서 바로 답변한다.
- 코드 변경·터미널 실행·장시간 탐색이 **불필요**한 요청에 해당한다.
- **예외**: 다수 파일·아키텍처 수준 **코드 리뷰**는 질문-only가 아니며 아래 override·1~2단계 판단으로 넘긴다.
### 사용자 override (최우선)
아래가 요청에 명시되어 있으면 1~2단계 판단을 건너뛰고 3→4단계로 진행한다.
- **위임 강제**: `claude로`, `Claude Code로`, `claude에게` 등 → Claude Code 위임 (CLI 불가 시 Cursor 직접 처리 폴백)
- **직접 강제**: `cursor로`, `Cursor로`, `cursor에서` 등 **실행 주체를 명시**한 경우만 (예: "이 함수 직접 수정해줘"는 해당 없음)
- `[이유]`에 `사용자 override`를 포함한다.
### CLI 확인 (위임·override 위임이 필요할 때만)
질문-only(위) 또는 직접 강제 override면 이 확인을 생략한다.
1. `command -v claude`로 바이너리 존재 확인
2. `claude --version`으로 실행 가능 여부 확인 (비零 종료·인증 오류 시 CLI 불가로 간주)
CLI 불가 시 Cursor가 직접 처리한다. 사유는 3단계 `[이유]`에 한 줄로 포함한다.
## 1단계: 빠른 분류 (fast-path)
### 단순 수정
다음 **모두**에 해당하면 Cursor 직접 처리로 확정하고 2단계를 생략한 뒤 3→4단계로 진행한다.
- 단일 파일·오타·짧은 함수 수준의 단순 수정
- 사용자가 파일·선택 영역·함수명 등 수정 대상을 문장으로 지정함(또는 에디터에 해당 파일이 열려 있음)
- 아래 2단계 위임 조건에 해당하지 않음
## 2단계: 실행 주체 판단 및 계획서 (위임·애매할 때)
1단계 fast-path로 확정되지 않았을 때만 수행한다.
### 실행 주체 판단
다음 기준으로 Cursor(나 자신)와 Claude Code 중 하나를 선택한다.
**판단 우선순위**: 아래 위임 조건 중 하나라도 해당하면 Claude Code를 선택한다(“열려 있는 파일”만으로 직접 처리로 내리지 않는다).
**Claude Code로 위임하는 경우:**
- 여러 파일에 걸친 대규모 리팩토링
- 터미널 명령 다수 실행 필요 (빌드, 테스트, 마이그레이션 등)
- 장시간 자율 작업(에이전틱 루프)이 필요한 경우
- 코드베이스 전체 탐색 후 판단이 필요한 디버깅
**Cursor(나 자신)가 직접 처리하는 경우:**
- 현재 열려있는 파일/선택 영역 기반의 단순 수정
- 빠른 응답이 중요한 소규모 변경
- 사용자가 이미 컨텍스트를 지정해준 작업
- 인라인 코드 제안이나 짧은 함수 단위 작업
**애매한 경우(예: 파일 2~5개, 중간 난이도)**: 변경 파일 수·터미널 필요 여부·코드베이스 탐색 범위 중 **2개 이상**이 위임 조건에 해당하면 Claude Code를 선택한다.
**CLI 불가(0단계)**: 위임 조건을 만족해도 Cursor가 직접 처리하되, 위임이었다면 쓸 계획서 수준으로 탐색·터미널 검증을 수행한다(능력 한도 내).
### 작업계획서 (내부 추론용, 사용자에게 출력하지 않음)
위임 또는 애매한 경우에만 다음 네 항목을 **내부에서만** 정리한다. 사용자 메시지에는 3단계 `[판단]`/`[이유]`만 출력한다.
- 작업 목표
- 예상 변경 범위 (파일 수, 신규/수정/삭제 여부)
- 예상 난이도 (단순 수정 / 중간 로직 / 아키텍처 설계 수준)
- 예상 소요 컨텍스트 (단일 파일 vs 멀티 파일 vs 전체 코드베이스 이해 필요)
## 3단계: 판단 결과 및 이유 먼저 출력
질문-only로 0단계에서 확정된 경우 이 단계를 생략할 수 있다.
그 외에는 다음 형식으로 먼저 답한다. 이 두 줄 외 부연 설명 없이:
[판단] Claude Code 위임 / Cursor 직접 처리
[이유] (한 줄; CLI 불가·사용자 override 시 여기에 포함)
## 4단계: 실행
- **Claude Code 선택 시**: 작업 루트(모노레포면 대상 패키지 디렉터리)에서 PATH의 `claude`로 위임 실행 (경로 하드코딩 금지)
  프롬프트는 작업계획서 4항목을 1~2문장으로 요약한 뒤 사용자 원문 지시를 붙인다.
  따옴표·백틱이 포함되면 heredoc 또는 단일 인용으로 이스케이프한다.
  예: `claude -p '목표: … 범위: … 지시: …'`
  실행 후 **위임 후 최소 검증**을 수행한다:
  1. `git status` 등으로 변경 파일 목록 확인
  2. 프로젝트에 테스트 스크립트가 있으면 관련 범위 1회 실행
  3. 검증 결과를 요약 보고에 포함 (실패 시 실패 로그 요약)
  - **실패 시**(비零 종료, 타임아웃, 빈 출력): 1회 재시도 후에도 실패하면 사용자에게 한 줄 알리고 Cursor가 동일 작업을 직접 이어서 처리한다.
  - Shell 타임아웃은 작업 규모에 맞게 설정한다(단순: 120초, 대규모: 600초 이상).
- **Cursor 직접 처리 선택 시**: 바로 코드 수정·설명 진행. 계획 재설명 없이 결과만 제시.
---
## 참고 (팀 공유 시)
- 이 커맨드는 `claude`가 PATH에 잡혀 있고 `claude --version`이 성공한다는 전제로 위임한다.
- 팀원별 설치 경로(예: nvm, npm-global, homebrew 등)가 달라도 PATH만 잡혀 있으면 동일하게 동작하므로 절대경로를 커맨드 안에 넣지 않는다.
- CLI 불가 팀원은 0단계에서 자동으로 Cursor 직접 처리로 폴백되므로 별도 에러 없이 협업 가능.
